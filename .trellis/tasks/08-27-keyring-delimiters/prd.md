# 04 key 串分隔符健壮性

## Parent

`.trellis/tasks/08-26-issue-triage-batch` — 见其 `prd.md` 与 `design.md`。

## What to build

多 key 配置目前只认英文半角逗号。用户若用全角逗号，整串会被当成**一个** key——每次请求都认证失败，而且因为环里只有一个凭证，轮换根本不会触发。症状就是「配一个 key 一切正常，配两个 key 立刻全挂」，而失败信息指向 key 无效，完全看不出真正的问题是分隔符。

扩展切分：英文逗号、全角逗号、中英文分号、空白与换行都作为分隔符。合法 key 是固定前缀加字母数字，不可能包含这些字符，因此切分没有误伤风险。

**同时保留告警。** 只做切分等于默默纵容错误输入，用户下次换个更奇怪的分隔符还会踩同一个坑。切分后只得到一段、且该段含非 ASCII 字符时，发出明确告警。

## Acceptance criteria

- [ ] `,`、`，`、`;`、`；`、空白、换行均可作为分隔符
- [ ] 混用多种分隔符时切分正确
- [ ] 切分后只剩一段且该段含非 ASCII 字符时发出告警
- [ ] 告警中不出现完整 key
- [ ] 单 key 配置的行为完全不变
- [ ] 空值或全是分隔符的值仍退化为原有的单 key 行为（交由上游返回认证错误）
- [ ] 切分逻辑对所有复用 key ring 的上游一致生效
