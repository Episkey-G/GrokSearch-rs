# 09 客户端侧工具调用的失败分类

## Parent

`.trellis/tasks/08-26-issue-triage-batch` — 见其 `prd.md` 与 `design.md`。

## What to build

有些 OpenAI 兼容网关不把网页搜索当作服务端工具执行，而是回一轮「请你去执行这个搜索函数」，等客户端把结果送回来再给最终答案。现在遇到这种响应，解析器看到内容为空、来源为空，归类成笼统的解析错误——用户看到的是「响应为空且没有来源」，完全看不出真正的原因是 transport 不兼容，很容易误以为是自己的 query 有问题。

给这种情况一个专属的失败类别，并带上网关请求的函数名，让用户能判断该换网关还是换配置。

**不实现二次调用。** 不去执行网关要求的搜索函数、也不发起追加请求。理由见父任务的 Out of Scope：只影响非 Grok 的兼容网关，需要引入无界工具循环的防护面，目前只有一位报告者。

## Acceptance criteria

- [ ] 响应表明网关在请求客户端执行工具、且没有最终内容时，返回专属失败原因
- [ ] 该失败原因包含被请求的函数名
- [ ] 该原因与既有的解析错误分类可区分
- [ ] 正常单轮响应的解析路径完全不受影响（既有的四条来源提取路径全部保持）
- [ ] 不发起任何追加请求
- [ ] 非搜索类的工具调用不被特殊处理，也不被隐式执行
