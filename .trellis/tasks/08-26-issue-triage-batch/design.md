# 技术设计：issue 分诊落地

约束前提：术语依 `CONTEXT.md`；时间预算依 `docs/adr/0001-one-deadline-per-search.md`。

## Implementation Decisions

### 1. stdio transport 的并发调度

- **拆出可测核心。** 当前的 stdio 入口把「读一行 → 处理 → 写一行」和真实 stdin/stdout 焊在一起，调度逻辑没有任何接缝。拆成两层：一个只负责绑定真实 stdio 的薄壳，和一个接受任意 `AsyncBufRead` + `AsyncWrite` 的服务循环。并发逻辑全部住在后者。这是本任务唯一新增的接缝，理由见 Testing Decisions。
- **每条请求 spawn 一个 task**，服务实例按需 clone 进去（它已经是全 `Arc` 持有的 `Clone` 类型，无额外代价）。
- **并发上限 8，用信号量实现，超出的排队而非拒绝。** 无上限会让一个失控的 agent 开出几十路并发，把上游 key 直接打到 429——那正是本任务另一半要解决的问题。显式拒绝（对齐远程 HTTP transport 的 429 语义）对本地 stdio 过于激进：本地场景排队等待是可接受的，而远程 transport 面对的是多租户，两者语义本就不该相同。
- **stdout 写入用互斥锁串行化**，锁的粒度是「一条完整响应 + 换行」，保证并发下不出现半行交错。
- **runtime 保持 current_thread。** 全部工作是 async I/O，换 multi_thread 只增加线程开销。DNS 解析走 reqwest 自己的 blocking 线程池，不受影响。
- **响应乱序是合法的**，JSON-RPC 用 `id` 配对。不引入任何保持顺序的机制。
- **无 `id` 的通知仍然不产生响应**，语义不变。

### 2. key ring 通用化

- **提取为共享模块。** 目前 key ring 私有于 Tavily provider。提到共用位置，Tavily / Grok Responses / OpenAI 兼容三方复用同一份实现与同一套轮换判定。
- **分隔符扩展**：`,`、`，`、`;`、`；`、空白与换行都作为分隔符。合法 key 是 `tvly-` / `xai-` / `sk-` 前缀加字母数字，不可能包含这些字符，因此切分零风险。
- **同时保留告警**：切分后只得到一段、且该段含非 ASCII 字符时，发出明确告警。只做切分而不告警等于默默纵容错误输入，用户换个更奇怪的分隔符还会踩同一个坑。

### 3. AI 上游的凭证轮换接缝

- **扩展凭证抽象，而不是绕过它。** 轮换判定需要看 HTTP 状态码，而 Grok Responses provider 取 key 走的是凭证抽象（只返回 bearer token，不感知状态码）。给该抽象增加「凭证总数」与「取第 N 个凭证」两个能力，静态 API key 实现内部持有 key ring，OAuth 实现回答 1 且忽略序号。轮换循环仍留在 provider 的 POST 层——那里才看得到状态码。
- **不选「provider 直接持 key ring、绕过凭证抽象」**：那会让 Grok provider 长出两条取凭证路径，OAuth 那条以后每次改动都要同步维护。
- **向后兼容**：新增能力带默认实现，现有实现者无需改动。这也是本决策**不需要 ADR** 的原因——改回去的成本接近零，过不了「hard to reverse」。
- **轮换触发条件沿用现有 key-scoped 判定**（401/403/429 及各上游的配额状态码）；5xx 与超时是上游范围的问题，换 key 只是徒增延迟，不触发轮换。

### 4. 重试语义

- **整个重试序列包在 request deadline 内**（ADR-0001）。当前 AI 调用外层没有任何 deadline，只受 HTTP client 超时约束；若不加约束，N 个 key × M 次重试会把最坏耗时乘上去。
- **重试上限 2 次，退避 250ms → 1s。**
- **退避前必须检查剩余预算**：`Retry-After` 指示的等待超过剩余预算时不睡眠，直接放弃该次尝试，把控制权交还给 source fallback。
- **重试与轮换是两件事**：轮换换的是凭证，重试重发的是同一个凭证的请求。两者共享同一个预算。
- **默认时间预算从 60s 下调到 45s**，使服务端总能在 60s 量级的客户端工具超时之前把分类好的错误说完。

### 5. 诊断可见性

- **配置文件加载结果进入 `doctor`**：报告路径、是否加载成功、失败原因。严格校验本身不变——未知键仍然导致整个文件被拒绝，只是拒绝这件事不再只写到 stderr（MCP 客户端下不可见）。不放宽为「警告未知键并保留其余」，那会推翻配置模板里明写的设计意图。
- **空 source chain 的失败说明改写**：当 chain 为空时，说明必须指向「未配置任何 source provider」并列出可选项。`no_specialist_match` 这个措辞只在 chain 非空、确实没有 specialist extractor 匹配时保留。这条文案正是把 #39 报告者误导成「specialist 需要 key」的源头。
- **客户端侧工具调用识别为独立失败类别**：OpenAI 兼容响应带 `finish_reason: "tool_calls"` 且无最终内容时，返回专属失败原因并带上被请求的函数名，不再落进笼统的解析错误分类。

## Testing Decisions

**什么是好测试**：只断言外部可观测行为——请求进去、响应出来、上游收到了什么、用户看到了什么。不断言私有结构、不断言调用次数以外的内部状态、不对实现细节做快照。并发测试断言的是「重叠窗口存在」和「id 配对正确」，不是「谁先谁后」。

**接缝选择原则**：优先复用已有接缝，新接缝取尽可能高的位置。本任务横跨 transport / provider / service / adapter 四层，无法收敛到单一接缝，但除 stdio 外没有一处需要为测试新开口子。

| 被测行为 | 接缝 | 状态 | Prior art |
| --- | --- | --- | --- |
| stdio 并发、乱序配对、上限排队 | 接受任意 reader/writer 的服务循环，用内存双工管道驱动 | **新增** | 现有 stdio 模块内的单消息处理测试 |
| key 轮换的凭证序列 | mock HTTP server + provider，断言观测到的 `Authorization` 头序列 | 已有 | Tavily 轮换测试（`std::net::TcpListener` + 后台线程，零新依赖） |
| 重试不越界、空链文案 | 搜索服务顶层 + 假 provider 构造器 | 已有 | 服务契约测试中既有的 deadline 边界用例 |
| 配置加载可见性 | `doctor` 输出 | 已有（当前零覆盖） | 配置加载测试 |
| tool_calls 失败分类 | chat completions 响应解析纯函数 | 已有 | OpenAI 兼容适配器测试 |
| key 串切分与告警 | key ring 解析纯函数 | 已有 | Tavily 轮换测试内的解析用例 |

**需要新建的夹具**：写坏的配置文件（临时目录）；能被观测到执行窗口的慢假 provider；按脚本返回 401/429/503 序列的 mock 上游。最后一项直接复用 Tavily 轮换测试里的 mock server 骨架。

**回归保护重点**：stdio 的既有行为（版本协商、通知不回响应、解析错误码）必须在并发化之后逐条重测——这是本批次唯一改动所有用户热路径的变更。

## 交付顺序与发布

四个子任务，前两个互不阻塞，后两个依赖前两者的结论：

1. **stdio 并发**（含接缝拆分）— 单独发布 0.1.25
2. **key ring 通用化 + 分隔符 + AI 上游轮换重试 + 默认预算下调**
3. **诊断可见性三项**
4. **文档** — 依赖 1–3 的最终措辞

2–4 合并发布 0.1.26。1 单独先发，因为 #39 影响所有 stdio 用户，不应等待 #14 完成。

**实现前置**：分支必须从 `origin/main` 切出（本地 `main` 落后 11 个提交），且工作树中 30 个未提交路径（doctor/setup WIP，与本任务改动文件重叠）需先处置。
