# 07 配置加载结果进入 doctor

## Parent

`.trellis/tasks/08-26-issue-triage-batch` — 见其 `prd.md` 与 `design.md`。

## What to build

用户设了 key 和自定义 endpoint，诊断工具却报告「未配置」，而且 endpoint 显示的是默认值。用户无从判断是自己写错了、文件根本没被读取，还是部署方式不支持这项覆盖。

根源是配置文件的加载失败只写到 stderr——而 MCP 客户端把 stderr 吞掉了，用户永远看不见。配置文件采用严格校验：任何一个未知键会导致**整个文件**被拒绝，于是一个拼写错误就让所有配置静默回落到默认值。

让诊断工具报告配置文件的路径、是否加载成功、失败原因。

**严格性本身不变。** 不放宽为「警告未知键并保留其余键」——那会推翻配置模板里明写的设计意图（未知键必须是错误，不能静默丢弃）。这张票只让失败**可见**。

## Acceptance criteria

- [ ] 诊断输出包含配置文件的解析路径、加载结果、失败原因
- [ ] 含未知键的配置文件仍然整体被拒绝（严格性不变）
- [ ] 该拒绝的具体原因（哪个键、什么错误）出现在诊断输出中
- [ ] 配置文件不存在时，如实报告「未找到」而非「加载失败」
- [ ] 配置文件加载成功时，诊断输出如实反映
- [ ] 诊断报告的各上游 endpoint 与实际会被调用的 endpoint 一致
- [ ] 公共契约检查脚本仍然通过
